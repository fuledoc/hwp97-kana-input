# Hangul Phonetic 변환 정책

## 지위와 범위

이 문서는 이 프로젝트가 선택한 Hangul Phonetic 동작을 설명한다. 일본어 번역·형태소 분석·표준 전사 규칙이 아니며, 한글97 바이너리나 사전에서 추출한 자료도 아니다.

`test/fixtures/hangul-phonetic.golden.json`은 사람이 검토하는 실행 가능한 회귀 계약이고, 이 문서는 그 계약의 근거와 한계를 기록한다. `src/kana-engine.js`는 구현이다. 세 파일이 어긋나면 기대값을 자동 갱신하지 말고 정책 변경인지 구현 결함인지 먼저 결정한다. `docs/research.md`의 링크는 배경 자료이며 규범적 근거가 아니다.

## 입력과 정규화

- 완성형 한글 음절은 음절 단위로 변환한다. 앞뒤 문맥이나 단어 사전을 사용하지 않는다.
- 결합형 Hangul Jamo 연속 구간은 NFC로 조합한 뒤 변환한다.
- 호환 자모와 한글이 아닌 Unicode는 아래 문장부호 규칙에 해당하지 않으면 코드 포인트 순서를 그대로 보존한다.
- 출력 문자종은 `hiragana` 또는 `katakana`이다. Katakana 출력은 같은 Hiragana 결과를 문자종 변환한 것과 같아야 한다.

## 음절 근사

- 초성 `ㅇ`은 모음 행으로 처리하고, 다른 초성은 프로젝트의 가나 행 표에 대응한다.
- 중성은 가까운 일본어 모음 또는 요음으로 근사한다. 특히 `ㅓ`는 o 계열, `ㅝ`는 wo 계열, `ㅢ`는 ui 계열로 처리한다.
- `ㅈ/ㅉ/ㅊ + ㅜ`는 각각 `じゅ`, `っじゅ`, `ちゅ`로 처리한다.
- 경음 초성은 대체로 작은 `っ`과 해당 가나를 결합한다.

## 종성

종성은 일본어 철자를 추론하지 않고 다음 세 부류로 축약한다.

- 종성 없음: 아무 문자도 덧붙이지 않는다.
- `ㄴ, ㄵ, ㄶ, ㅁ, ㅇ`: `ん`
- `ㄹ, ㄺ, ㄻ, ㄼ, ㄽ, ㄾ, ㄿ, ㅀ`: `る`
- 그 밖의 종성: `っ`

이 규칙은 발음 환경과 어휘를 보지 않는 의도적인 단순화다.

## 문장부호와 통과

`-`는 `ー`, `,`는 `、`, `.`는 `。`, `?`와 `!`는 전각 물음표·느낌표로 변환한다. 대괄호는 `「」`, 소괄호는 전각 소괄호, `/`는 `・`로 변환한다. 그 밖의 문자는 그대로 통과한다.

## Provisional 결정

골든 코퍼스의 `status: "provisional"`은 현재 결과를 회귀 스냅샷으로는 지키되 정책이 충분히 검증되지 않았음을 뜻한다.

- 모든 종성 축약 사례는 실제 일본어 어휘와 문맥에 따라 달라질 수 있다.
- `tense-jju`의 `쭈 → っじゅ`는 경음 규칙과 특수 `ㅈ + ㅜ` 규칙을 기계적으로 결합한 결과다.
- `vowel-wo`의 `워 → うぉ`는 모음 근사이며 일본어 철자를 보장하지 않는다.

`provisional`도 테스트에서는 일반 사례와 동일하게 강제한다. 상태가 없는 사례 역시 역사적·언어학적 정답을 의미하지 않고 현재 프로젝트가 채택한 계약이라는 뜻이다.

## 알려진 한계와 UI 보완

- **목적격 조사 「を」는 Hangul 발음으로 입력할 수 없다.** 현대 일본어에서 「を」는 조사로만 쓰이는데, 어떤 한글 음절도 「を」로 매핑되지 않는다. 모음 wo(워)는 `うぉ`(외래어 ウォ)로 가고, 오(ㅇ+ㅗ)는 `お`로 간다. 이 상충 때문에 매핑을 뒤집지 않는다. 대신 화면의 「특수 글자」 빠른삽입 버튼으로 「を」를 직접 넣는다. Romaji 모드에는 `wo → を`가 있어 재현 가능하다.
- **가타카나 외래어 말미 ㄹ→る는 의도된 유익 동작이다.** 종성 ㄹ계열→`る` 규칙 덕분에 `호텔 → ホテル`, `모델 → モデル`, `오르간 → オルガン`처럼 한국어 받침 습관대로 쳐도 올바른 가나가 나온다. `provisional`이라는 라벨과 달리 이 용도에서는 안정적이므로 실수로 되돌리지 않는다. 회귀 계약: 골든 `loanword-hotel-coda-r`.
- **탁음/청음은 초성 종류로 갈린다.** 평음 초성 ㄱㄷㅂㅈ은 탁음(が·だ·ば·ざ), 격음 초성 ㅋㅌㅍㅊ은 청음(か·た·ぱ·ちゃ)에 대응한다. 따라서 `도쿄`는 `どきょ`가 되고 정확한 東京은 `토우쿄우 → とうきょう`로 입력한다. 엔진은 그대로 두고 화면 도움말의 치트시트로 안내한다. 회귀 계약: 골든 `learnability-tokyo-plain-k`.

## 골든 코퍼스 변경 규칙

- 각 사례는 고유하고 안정적인 `id`, `category`, 원문 `input`, 명시적인 `script`, 리터럴 `expected`를 가진다.
- 기대값을 현재 엔진 출력에서 생성하거나 테스트를 통과시키기 위해 일괄 덮어쓰지 않는다.
- 정규화에 민감하거나 눈으로 구별하기 어려운 문자는 JSON의 `\uXXXX` 표기를 사용한다. 로더는 입력을 trim하거나 정규화하지 않는다.
- 의도적인 정책 변경은 구현, 골든 코퍼스, 이 문서를 같은 변경에서 갱신한다. 구현 결함 수정은 재현 사례를 코퍼스에 추가한다.
- 전체 11,172개 완성형 음절 테스트는 한글 잔존 없음과 문자종 대칭만 검증한다. 개별 출력의 언어학적 타당성을 증명하지 않는다.
